32 // The modeler side of the last optimisation pass of a week, kept alive past the
33 // solve so a post-process dump can re-emit the modeler component rows.
34 //
35 // Cheap to hold, but only because the lifetime is kept tight at both ends. The
36 // MPSolver holding the actual problem data is also in
37 // PROBLEME_ANTARES_A_RESOUDRE::ProblemesSpx for as long as this lives, so what
38 // the retention adds is the wrapper objects -- and OrtoolsMipVariable only wraps
39 // a raw MPVariable*. OPT_TryToCallSimplex drops the previous value before

67 // Publishes the results as they stand *after* post-processing.
68 //
69 // In hybrid mode the modeler component rows are re-emitted first, from
70 // PROBLEME_HEBDO::lastSolvedModelerProblem, so a stage table describes the whole
71 // system rather than only its legacy half. Their values are necessarily the ones
72 // the solver left: post-processing mutates the legacy result structures only, and
73 // cannot move a modeler variable.
74 //
75 // Post-processes (remix hydro / shave-peaks, the adequacy patch, ...) mutate
76 // PROBLEME_HEBDO's result structures in place and never write back into
77 // ProblemeAResoudre::X, so a plain fill would re-emit the values the solver
78 // left. AdresseOuPlacerLaValeurDesVariablesOptimisees already points at the
79 // exact result slot of each variable -- OPT_AppelDuSimplexe publishes with
80 // `*address = X[i]` -- so reading those addresses back into X republishes the
81 // post-processed state and lets the regular fill be reused unchanged. The same
82 // holds for the duals through AdresseOuPlacerLaValeurDesCoutsMarginaux, which
83 // UpdateMrgPriceAfterCSRcmd overwrites in place.
84 //
85 // X and the duals are restored before returning, so calling this cannot change
86 // anything the simulation computes afterwards.
87 //
88 // Does nothing (with a one-time warning) when the simplex optimization range is
89 // daily: the week is then solved in seven intervals that each rebuild the
90 // address table, so only the last day would be readable here.
91 void DumpSimulationTableAfterPostProcess(
92  Antares::IO::Outputs::SimulationTable& simulationTable,
93  PROBLEME_HEBDO& problemeHebdo,
94  const Antares::LinearProblem::Api::FillContext& fillContext,
95  unsigned currentBlock);
